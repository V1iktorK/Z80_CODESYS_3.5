## Девять дефектов, найденных запуском (и исправленных)

Все они невидимы компилятору: проект собирался с 0 ошибок.

| № | Дефект | Как проявился |
|---|---|---|
| 63 | `FB_Clock` строился на фронтах `Scan`, а `Scan` всегда `TRUE` | `Clk_Decode` застрял в `TRUE`, `Clk_Exec` не возникал никогда → PC не двигался |
| 64 | `Ctl_Imm_Mode` не включал `JP`/`JP Z`/`JP NZ` | для `JP 0FA00h` адрес операнда брался из `HL` (=0), память читала опкод по адресу 0 |
| 65 | `Init_PC` нигде не читался в `PLC_PRG` | каждый тест начинался с PC=0, а не с `Init_PC` (0120h / 0140h) |
| 66 | `vRun := Emu_Run` без учёта `Halted` | `HALT` распознавался (`Halted=TRUE`), но такт продолжал идти и PC уезжал за 2500 |
| 67 | `Inc` счётчика PC был константой `TRUE` | PC прирастал **каждый скан**, а команда занимает два скана → PC перескакивал байты, в т.ч. `HALT` |
| 68 | У `FB_RegFileZ80` **не было хранения регистров** | стропы `WE_0..WE_15` вычислялись, но ни один регистр не запоминал значение: все регистры вечно 0 |
| 69 | `Init_Sel_Dst` никто не перебирал | инициализация могла загрузить только один регистр (A), остальные оставались нулями |
| 70 | Запись регистров тактировалась `Clk_Exec`, а при инициализации такт стоит | `Init_Vals` молча отбрасывались: `A=12h` в `Init_Vals`, `A=0` в регистре |
| 71 | Регистр флагов не инициализировался из `Init_Vals[7]` | `Init_F = FFh`, а `GVL_PLCVisu.F = 00h` → все тесты «флаги не должны меняться» падали |

Плюс два дефекта стенда: массив `Cpu_Tests` был `[1..40]`, а циклы шли до 75
(выход за границы, эмулятор «застревал» на `Cpu_Test_Active = 44`).

### Что теперь работает (проверено на исполнении)

Программа `4 NOP` + `HALT`:

```
PC: 0 → 1 → 2 → 3 → 4 → 5 → стоп
IR = 118 (76h = HALT),  Halted = TRUE,  vRun = FALSE
```

Процессор выбирает команду, декодирует, инкрементирует PC с правильной
длиной и останавливается по `HALT`. Инициализация регистров и PC из
`GVL_InitRegs` работает.

## Что осталось и почему это не мелочь

Осталось **архитектурное противоречие в тракте операнда**, и оно требует
переделки, а не заплатки.

`FB_Memory64K` имеет три порта: выборка по `PC`, операнд по `Addr` и стек по
`SP_Addr`. Для `LD r,n` нужен байт по адресу `PC+1`; для `LD A,(nn)` — байт по
адресу `nn`, а сам `nn` лежит в `Mem[PC+1]` и `Mem[PC+2]`.

В текущей схеме `vAddr = Imm_Mode ? nn : HL`, а `nn` собирается из
`Rd_Data` (порт операнда) и младшего байта `SP_Out` (порт стека, у которого
адрес — `fbSP.SP`, а не `PC+1`). То есть для 8-битных непосредственных команд
адрес операнда получается **значением операнда**, а не `PC+1`.

Замер: `LD B,2Ah` — в памяти `06 2A`, в регистре B остаётся 0, потому что
память читается по адресу `2Ah`, а не по `1`.

**Что нужно:** развести тракт операнда на два случая (`PC+1` для 8-битных и
`nn` для 16-битных) и добавить памяти четвёртый порт либо переключать адрес
стека на фазу исполнения. Это изменения в `FB_Memory64K`, сетях `SET 6`,
`SET 7` и в подключении `SP_Addr`, с последующей перенастройкой всех 40
проверок.

## Честная оценка

* **Сборка:** 0 ошибок, 0 предупреждений по коду — как и было.
* **Исполнение:** процессор шагает, но **команды не выполняют своих
  действий**. 0 из 40 и 0 из 30.
* **Вывод:** прошлая формулировка «готов как проект для сдачи, но эмуляция
  не проверена» была оптимистичной. Правильная формулировка: **эмулятор
  нерабочий**, и это выяснилось только сейчас, когда появился доступ к
  настоящему запуску.

Работать дальше нужно именно по этой линии — с запуском после каждого шага.
Компилятор тут больше не помощник: он молчит при 0 ошибок на нерабочей схеме.
