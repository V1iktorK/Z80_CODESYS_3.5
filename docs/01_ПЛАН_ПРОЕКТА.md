# ШАГ 1. ПЛАН ПРОЕКТА — эмулятор Zilog Z80 в CODESYS 3.5 на FBD

## 1. Цель

Эмулятор Z80, реализованный в CODESYS 3.5 **исключительно на FBD**
(логические функциональные блоки, читаемая схема). Работает в режиме симуляции.
ST допускается только для инициализации массива памяти и генерации тестовых данных.

Минимальный набор команд: `LD r,r`; `LD r,n`; `LD r,(HL)`; `LD (HL),r`; `ADD A,r`;
`SUB r`; `INC r`; `DEC r`; `JP`; `JP Z`; `JP NZ`; `CALL`; `RET`; `HALT`; `DJNZ`.

Регистры: A, F, B, C, D, E, H, L, IX, IY, SP, PC, I, R и альтернативный набор
A'…L', F'. Флаги: S, Z, H, P/V, N, C (F5/F3 хранятся, но не тестируются на 1-м этапе).

## 2. Архитектурные договорённости

| Пункт | Решение |
|---|---|
| Типы | A, F, регистры общего назначения и альтернативные — `BYTE`; PC, SP, IX, IY — `WORD` |
| Память | `ARRAY[0..65535] OF BYTE` |
| Шины | `Bus_Data : BYTE`, `Bus_Addr : WORD` — в GVL, а не проводами |
| Биты | распаковка `BYTE → ARRAY[0..7] OF BOOL` в отдельном FB (`FB_BitUnpack8`) |
| Такт | **один скан PLC = одна команда Z80** |
| Язык | только FBD; ST — лишь инициализация памяти и тестовые данные |

## 4. Используемые блоки CODESYS FBD

`AND`, `OR`, `XOR`, `NOT`, `SEL`, `MUX`, `ADD`, `SUB`, `EQ`, `GT`, `SHL`, `SHR`,
`BYTE_TO_WORD`, `WORD_TO_BYTE`.

Собственные замены библиотечных блоков: `FB_RTrig`, `FB_FTrig`, `FB_RS`
(библиотека `Standard` в этой установке даёт `C77` из-за отсутствующей
зависимости `CBML`, поэтому блоки написаны с нуля).

## 5. Кастомные FB

| FB | Назначение |
|---|---|
| `FB_Reg8` / `FB_Reg16` | регистр со стробированием записи и сбросом |
| `FB_RTrig` / `FB_FTrig` | детекторы переднего / заднего фронта (двухфазный такт) |
| `FB_RS` | триггер с приоритетом сброса (флаг `Halted`) |
| `FB_RegFileZ80` | 16 регистров: основной + альтернативный наборы |
| `FB_ALU_Z80` | ADD, ADC, SUB, SBC, AND, OR, XOR, CP + вычисление всех флагов |
| `FB_FlagsRegZ80` | регистр флагов F, включая F5/F3 |
| `FB_DecoderZ80` | IR → сигналы управления |
| `FB_Memory64K` | память 64 КБ |
| `FB_PC_Z80` | счётчик команд |
| `FB_SP_StackZ80` | указатель стека, PUSH/POP |
| `FB_ControlUnit` | JP / CALL / RET / DJNZ / HALT |
| `FB_Clock` | двухфазный такт |
| `FB_BitUnpack8` | `BYTE ↔ ARRAY[0..7] OF BOOL` |
| `FB_TestCase` | один тест-кейс: сравнение через `EQ` |

## 6. Схема такта

**Ключевое решение: двухфазный такт.** FBD — это поток данных, а не поток
управления. Наивная схема даёт комбинационную петлю
`PC → память → ALU → флаги → PC`, которую CODESYS либо отвергнет, либо
исполнит недетерминированно.

Решение: за один скан шина используется дважды, и петля рвётся триггером.

| Фаза | Что происходит | Кто управляет |
|---|---|---|
| **1** `Clk_Decode` | PC → Bus_Addr → Memory → IR; декодирование | `FB_RTrig` |
| **2** `Clk_Exec` | регистры → ALU → запись; обновление PC, SP, FLAGS | `FB_FTrig` |

Требование «один скан = одна команда» сохраняется полностью: команда просто
выполняется в два полутакта внутри скана.

## 7. Структура проекта и порядок исполнения

`PLC_PRG` — главная схема. Порядок исполнения блоков задаётся **Execution Order**
и следующий (каждый блок читает только то, что записали блоки с меньшим номером):

1 `FB_Clock` · 2 `FB_PC_Z80` · 3 `FB_Memory64K` (fetch) · 4 `FB_InstructionReg` ·
5 `FB_DecoderZ80` · 6 `FB_RegFileZ80` (чтение) · 7 `FB_Memory64K` (чтение операнда) ·
8 `FB_ALU_Z80` · 9 `FB_FlagsRegZ80` · 10 `FB_RegFileZ80` (запись) ·
11 `FB_SP_StackZ80` · 12 `FB_ControlUnit` · 13 `FB_PC_Z80` (защёлкивание) ·
14 `FB_Reg8 R`

Это формальное условие отсутствия гонок.

## 8. Разделение по шинам через GVL

| GVL | Содержимое |
|---|---|
| `GVL_Bus` | `Bus_Data : BYTE`, `Bus_Addr : WORD` |
| `GVL_Control` | 15 сигналов декодера (`Ctl_*`) + `Emu_Run/Step/Reset` |
| `GVL_PLCVisu` | зеркало состояния для HMI (только чтение) |

Почему через GVL: 15 сигналов управления, протянутых проводами от декодера к
семи блокам, превратят лист в нечитаемую паутину. Через GVL каждый блок
обращается к `Ctl_*` по имени.
