## 3. ЧТО ОСТАЛОСЬ СДЕЛАТЬ (это и есть задача следующей сессии)

### 3.1. Главное: сквозной запуск .COM не подтверждён

Измерено: `GVL_CPM.Bdos_Count = 0`, `GVL_CPM.Out_Count = 0` — перехват
`CALL 0005h → 0F000h → BDOS 9 → вывод в консоль` **ни разу не срабатывал**.
Тесты CP/M проверяют *состояние* (образ памяти, каталог, порты), а не
*исполнение программы*. В `docs/14_ОТЧЁТ_ФИНАЛ.md` и `README.md` формулировка
«запуск .COM» сильнее реальности — **исправить в первую очередь (шаг 0)**.

Два измеримых препятствия:

1. **`HELLO.COM` содержит команду вне набора.** В загрузчике `LD DE,0110h`
   (код `11h`) — 16-битная загрузка, в 16 командах ТЗ только 8-битная
   `LD r,n`. Декодер `11h` не распознаёт. Лечится: `LD D,01h` + `LD E,10h`.
2. **Конвейер.** Выборка кода идёт через общий экземпляр памяти **ниже**
   защёлки IR, поэтому IR отстаёт на команду: одиночная команда работает
   (на этом стоят 62 теста), программа из нескольких команд — нет.
   Пробное исправление (отдельный экземпляр `fbFetch` в сети защёлки) сломало
   4 теста переходов — **вероятная причина: лишний скан в стенде**
   (`2*Exp_Cycles + 1`). Проверить с `2*Exp_Cycles`.

## 5. ТЕХНИЧЕСКИЕ ФАКТЫ, БЕЗ КОТОРЫХ ВСЁ РАЗВАЛИТСЯ

### 5.1. Поведение FBD в CODESYS (каждое проверено измерением)

1. **Кольцо «выход → вход» внутри одного POU разрывается НУЛЁМ**, а не
   значением прошлого скана. Состояние — только через `GVL_Regs` (`Rs_*`/`Nx_*`)
   и защёлку `PRG_RegLatch` (в задаче после `PLC_PRG`).
2. **Переменная, читаемая в сети до своего `outVariable`,** даёт значение
   прошлого скана. Все промежуточные величины объявлять до вызова блока.
3. **Fan-out выхода блока:** у клона может остаться неподключённый вход.
   На каждого потребителя — свой `inVariable`; константы не переиспользовать.
4. **`b_sel(G, IN0, IN1)` даёт IN1 при G = TRUE.** Ошибка повторялась в проекте
   три раза — проверять порядок ветвей каждый раз.
5. **Выборка кода и чтение операнда — разные моменты:** защёлка IR в одной
   сети, операнд читается ниже (после декодера). Отсюда ограничение на
   программы из нескольких команд (см. п. 3.1).
6. **Память и регистры пишутся по стробу такта**, а данные записи — это
   результат АЛУ, который считается ПОСЛЕ чтения: запись выполняется
   следующим сканом (порт `Wr_Addr/Wr_Data/Wr_Stb`).

### 5.2. Инструменты CODESYS

* `--noUI` на этой машине **не работает** (пустой вывод, код 1). Обёртки
  запускают CODESYS через `Start-Process` с перехватом stdout/stderr и таймаутом.
* `app.build()` **не компилирует**; реальная компиляция — `app.generate_code()`;
  сообщения только в stdout/stderr, не в `system.get_messages()`.
* `InterfaceAsPlainText` обязан начинаться с `PROGRAM x` / `FUNCTION_BLOCK x` /
  `FUNCTION x : T` и не содержать тела; переводы строк — `&#xA;`.
* `BYTE_TO_BYTE` в CODESYS нет; `BOOL_TO_BYTE` возвращает USINT.
* CODESYS — **однопользовательское**: своя копия держит следующий запуск.
  Убивать только свои процессы (`--runscript`/`--noUI` в командной строке),
  не `taskkill /IM CODESYS.exe`.
* Скрипты для ScriptEngine — IronPython 2.7: без Python-3 синтаксиса,
  шестнадцатеричные константы через `0x3E`, не `16#3E`.
* Статические проверки запускаются обычным Python 3.

### 5.3. Разрешённый ST (проверяет `check_tz.py`)

`FB_Memory64K` (в FBD нет индексации массива), `PRG_InitMemory`,
`PRG_LoadTestProgram`, `PRG_CPM_Boot`, `PRG_CPM_BDOS`, `TEST_Z80_PREP`,
`TEST_Z80`, `TEST_Z80_CPM`. Всё остальное — FBD.
