## Где именно продолжать

**Блок A — тракт операнда.** Это то, что блокирует всё остальное.

Суть: у `FB_Memory64K` три порта — выборка по `PC`, операнд по `Addr`, стек по
`SP_Addr`. Для `LD r,n` нужен байт по `PC+1`, для `LD A,(nn)` — байт по `nn`,
а `nn` лежит в `Mem[PC+1]` и `Mem[PC+2]`. Сейчас адрес операнда вычисляется из
**значения** операнда: `LD B,2Ah` при памяти `06 2A` читает адрес `2Ah`.

Замер, подтверждающий это: `diag_ld.py` — B остаётся 0.

Что предстоит:
1. Развести 8-битный непосредственный операнд (`PC+1`) и 16-битный адрес (`nn`).
2. Дать памяти четвёртый порт **либо** переключать адрес стекового порта по
   фазе (`Clk_Decode` → `PC+1`, `Clk_Exec` → `SP`).
3. Проверить `SET 10`: пишется ли результат в нужный регистр (ни разу не
   исполнялось).
4. Только после этого имеют смысл флаги, `CALL`/`RET`/`DJNZ` и CP/M.

Правило, которое себя оправдало: **после каждой правки — прогон**, а не
накопление изменений. Сборка с 0 ошибок ничего не доказывает: схема была
нерабочей при полностью чистой компиляции.
