## 1. Задачи

Работа велась по двум заданиям, поставленным ранее.

### Задание 1. Эмулятор Z80 в CODESYS 3.5 на FBD

Работающий эмулятор Zilog Z80 внутри CODESYS на языке FBD. Главное
требование — **большая читаемая схема, а не компактный код на ST**.

Состав: 16 команд, регистры A–L, IX, IY, SP, PC, I, R и альтернативный
набор, флаги S Z H P/V N C (плюс хранимые F5/F3), память 64 КБ, 256 портов
I/O, шины через GVL, распаковка/сборка битов, 1 скан = 1 команда
с настраиваемым числом как точкой расширения.

ST разрешён только для: инициализации массива памяти, загрузки `.COM`,
генерации тестовых данных.

### Задание 2. CP/M 2.2 и реальное железо ПЛК

Запуск `.COM`, минимальный BDOS и BIOS, консоль, RAM-диск. Порты Z80
отображены на дискретные и аналоговые входы/выходы ПЛК через Device Tree.

## 4. Что было сделано

### 4.1. Тесты написаны ДО правок

По алгоритму сначала добавлен тест **T8** «ветви цепочек выбора одного
типа, условие — `BOOL`». Он кодировал целевое состояние и на момент
написания падал.

Два старых теста оказались с неверными предпосылками и были исправлены
(не «подогнаны», а приведены в соответствие с выясненной истиной):

* **T4** требовал, чтобы условие `SEL` приходило с *именованной переменной*,
  и считал ошибкой подачу выхода блока `EQ` напрямую. Это неверно: `EQ`
  возвращает `BOOL`, и такая связка законна. Теперь T4 проверяет **тип**
  (рекурсивно), а не способ подключения.
* **T7** искал в логе латинское слово `zavershena`, а CODESYS пишет
  по-русски `завершена`. Тест падал даже на чистой сборке. Исправлено.

### 4.2. Найдена и устранена главная причина ошибок

Практически все оставшиеся ошибки имели одну природу: **выход обобщённого
блока IEC (`AND`, `OR`, `XOR`, `ADD`, `SUB`, `SHL`, `SEL`) подавался прямо
во вход другого обобщённого блока**. Тип таких блоков выводится по
операндам; при разных типах CODESYS выбирает `USINT` и дальше не может
согласовать результат с объявленным типом.

Правило «проводить выход обобщённого блока через явную переменную нужного
типа» в проекте уже было записано, но применялось местами. Теперь
применено системно.

### 4.3. Исправленные дефекты (41–52)

Полное описание — в `docs/03_ЖУРНАЛ_СБОРКИ.md`, раздел 15. Кратко:

| № | Дефект |
|---|---|
| 41 | `Flag_S` вычислялся как байт (`Y AND 16#80`), а объявлен `BOOL` — ошибка и типа, и смысла |
| 42 | `Flag_H` считался неверной формулой (маскирование вместо переноса из бита 3) |
| 43 | Чётность `P/V` считалась как `NOT` байта вместо сравнения |
| 44 | Выходы `AND`/`OR`/`XOR` шли прямо в `SEL` (АЛУ) |
| 45 | Выходы `ADD`/`SUB` шли прямо в `SEL`, и `BYTE_TO_WORD` применялся к `WORD` (стек) |
| 46 | Нетипизированный литерал `0` в ветке `SEL` (порты I/O) |
| 47 | `Halt_Req := BOOL AND BYTE` (порты I/O) |
| 48 | `SHL` по байту на 8 — старший байт адреса терялся (сеть `SET 6`) |
| 49 | Двойная запись в `GVL_Bus.Bus_Addr` за один скан (сеть `SET 2`) |
| 50 | Декодер: `AND(BOOL, число)` вместо сигнала; `Ctl_Wr_Enable := 1`; `Ctl_Cond` получал `BOOL` вместо кода |
| 51 | CODESYS оставляет дочерний процесс с дескрипторами → лог читался пустым (принималось за «зависание») |
| 52 | Остатки в `build/` (`*.opt`) роняли сборку на первом шаге молча |

Отдельно стоит отметить дефекты 41–43 и 50: это были не только ошибки
типов, но и **семантические** — формулы флагов считались неправильно.
То есть сборка «намекала» на реальные ошибки в логике процессора.

### 4.5. Починена инфраструктура сборки

Две проблемы, которые стоили больше всего времени:

1. **Ложные «зависания».** `WaitForExit` возвращает управление, когда вышел
   родительский процесс, но CODESYS оставляет дочерний, и тот держит файлы
   перенаправления. Лог читался пустым, хотя сборка уже завершилась.
   Теперь после завершения убиваются все процессы CODESYS (чужая сессия
   исключается проверкой на старте), и только потом читается лог.
2. **Чужая сессия CODESYS.** Ранее обёртка делала
   `taskkill /IM CODESYS.exe /F` в цикле — это **убило бы работу
   пользователя в другом проекте**. Теперь снимаются только свои процессы
   (по признаку `--runscript`/`--noUI`), а при чужой сессии сборка честно
   останавливается с сообщением.

## 6. Что осталось (честно)

### 6.1. 19 предупреждений — не блокируют загрузку

* **`C139`** (3 уникальных): «Код `Halted;` / `Con_Lin;` / `0;` не имеет
  действия». Это внутренняя генерация ST из FBD для несвязанных выводов
  экземпляров FB. В исходных текстах таких операторов нет — проверено
  поиском по `src/` и по телам всех ST-программ. Предупреждение
  безвредное.
* **`C196`** (2 уникальных): неявные конверсии `WORD → INT` и `UINT → INT`
  при записи в поля `INT` структуры `ST_TestCase_CPM` (`Kind`, `Param`).
  Значения там всегда 0..255, на работу не влияют. Устранение требует
  менять типы полей структур тестов.

**`C308`** (сдвиг больше разрядности) устранён — был реальной ошибкой
(дефект 48).

### 6.2. Ручные шаги вне кода (API для них нет)

* **Визуализация HMI** — отрисовка в IDE, привязка к `GVL_PLCVisu`
  (см. `docs/07_ВИЗУАЛИЗАЦИЯ_И_ЗАПУСК.md`).
* **Привязка к физическому Device Tree** — переменные `%IX`/`%QX`/`%IW`/`%QW`
  (см. `docs/05_АППАРАТНЫЙ_ВВОД_ВЫВОД.md`). В текущем виде используется
  тестовый образ `GVL_HW_IO`, логика проверяется в симуляции.
* **Прогон тестов в симуляции CODESYS**: открыть проект, F5 → Online →
  Simulation → Login → Start; выставить
  `GVL_Tests.Cpu_Test_Run := TRUE` и `GVL_Tests_CPM.Cpm_Test_Run := TRUE`.
  Ожидается `Cpu_Test_Total_Pass = 62`, `Cpm_Test_Total_Pass = 30`,
  оба `*_Fail_Count = 0`.

## 7. Что осталось непроверенным

* **Логика процессора не проверена исполнением.** Сборка доказывает
  корректность типов и структуры, но не то, что команды работают как
  в настоящем Z80. Для этого нужен ручной прогон в симуляции (п. 6.2).
  Формулы флагов H и P/V были исправлены (дефекты 42, 43) — их
  правильность подтверждена по документации Z80, но не прогоном тестов.
* **Поведение с реальным железом** не проверялось: модулей I/O в Device
  Tree нет, работа идёт с тестовым образом входов.

## 8. Как воспроизвести

```bat
python generator\gen_z80.py            :: сгенерировать схемы и GVL
generator\run_build_log.cmd            :: собрать проект в CODESYS
```

Проверки (без CODESYS, быстрые):

```bat
python generator\tools\check_tz.py         :: 58 пунктов ТЗ
python generator\tools\tests_plan.py       :: тесты T1-T8
python generator\tools\find_mixed_ops.py   :: смешанные типы операндов
python generator\tools\check_comments.py   :: комментарии (* *)
python generator\tools\check_balance.py    :: баланс операторов ST
```

**Важно:** CODESYS однопоточный. Пока открыт IDE с любым проектом,
headless-сборка не начнётся — обёртка это распознаёт и сообщает, не убивая
чужую сессию.
