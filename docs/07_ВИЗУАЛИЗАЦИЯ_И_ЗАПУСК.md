# 07. ВИЗУАЛИЗАЦИЯ (HMI) И ЗАПУСК ЭМУЛЯТОРА

## 1. Почему визуализация создаётся вручную

Скриптовый API CODESYS **не имеет** метода создания визуализации: в полном
дампе API (272 104 строки, файл `_probe/scripting_api_dump.txt`) есть
`create_pou`, `create_gvl`, `create_dut`, `create_folder`, `create_task` —
и ни одного `create_visualization`. Поэтому визуализация добавляется в IDE
за один шаг, а вся её структура описана ниже.

Зато все **переменные** для визуализации уже созданы и заполняются схемой —
привязка сводится к перетаскиванию переменных на элементы.

## 2. Создание визуализации

1. Правый клик на `Application` → **Add Object** → **Visualization**.
2. Имя: `VISU_Z80`.
3. Создать три экрана (вкладки): `VISU_Registers`, `VISU_Memory`,
   `VISU_Console`. Либо одну страницу с тремя группами — на выбор.

**Почему привязка только к GVL:** все данные для HMI собраны в `GVL_PLCVisu`
и `GVL_CPM`. Внутренние переменные FB наружу не выходят, поэтому
визуализация физически не может повлиять на исполнение схемы.

## 3. Экран «Регистры»

| Элемент | Тип | Привязать к |
|---|---|---|
| A | Rectangle / Text | `GVL_PLCVisu.A` (формат `16#%02X`) |
| B, C, D, E, H, L | то же | `GVL_PLCVisu.B` … `GVL_PLCVisu.L` |
| A' | то же | `GVL_PLCVisu.AltA` |
| F | то же | `GVL_PLCVisu.F` |
| PC | то же | `GVL_PLCVisu.PC` (формат `16#%04X`) |
| SP | то же | `GVL_PLCVisu.SP` |
| IX, IY | то же | `GVL_PLCVisu.IX`, `GVL_PLCVisu.IY` |
| I, R | то же | `GVL_PLCVisu.I`, `GVL_PLCVisu.R` |
| IR | то же | `GVL_PLCVisu.IR` |
| Halted | Lamp | `GVL_PLCVisu.Halted` |

**Лампочки флагов** (8 лампочек в ряд, как на лицевой панели):

| Подпись | Переменная |
|---|---|
| S | `GVL_PLCVisu.FlagS` |
| Z | `GVL_PLCVisu.FlagZ` |
| H | `GVL_PLCVisu.FlagH` |
| P/V | `GVL_PLCVisu.FlagPV` |
| N | `GVL_PLCVisu.FlagN` |
| C | `GVL_PLCVisu.FlagC` |

**Кнопки управления:**

| Кнопка | Переменная | Действие |
|---|---|---|
| Run | `GVL_Control.Emu_Run` | разрешение работы эмулятора |
| Reset | `GVL_Control.Emu_Reset` | сброс процессора |
| CP/M загрузить | `GVL_BootFlags.Cpm_Reboot` | повторная раскладка перехватов и каталога |
| Память заново | `GVL_Control.Emu_Init` | повторная инициализация памяти |

## 4. Экран «Память»

| Элемент | Тип | Привязать к |
|---|---|---|
| Дампа памяти | **Table** | базовый адрес `GVL_PLCVisu.Dump_Base`, 16 строк × 8 байт |
| Адресная шина | Text | `GVL_Bus.Bus_Addr` |
| Шина данных | Text | `GVL_Bus.Bus_Data` |
| Скрытый указатель | Text | `Z80_Mem[GVL_PLCVisu.Dump_Base]` |

**Как сделать дамп в CODESYS:** в таблице задать адрес ячейки как
`Z80_Mem[GVL_PLCVisu.Dump_Base + <номер>]`. Прямая привязка к элементу
массива поддерживается: элемент можно привязать к `Z80_Mem[0]`, а адрес
менять через `Dump_Base`.

## 5. Экран «Порты I/O»

| Элемент | Привязать к | Комментарий |
|---|---|---|
| Дискретные входы (8 лампочек) | `GVL_HW_IO.DI_0` … `DI_7` | образ `IN 00h` |
| Дискретные выходы (8 лампочек) | `GVL_HW_IO.DO_0` … `DO_7` | образ `OUT 01h` |
| Аналоговый вход 0 | Text | `GVL_HW_Buffer.HW_In_AI0` |
| Аналоговый выход 0 | Text | `GVL_HW_Buffer.HW_Out_AO0` |
| Шина адреса I/O | Text | `GVL_IO.Bus_IO_Addr` |
| Шина данных I/O | Text | `GVL_IO.Bus_IO_Data` |
| Таблица портов | Table | `IO_Ports[0..255]` |

**Важно:** входы на этом экране можно задавать вручную в режиме симуляции —
именно так проверяются тесты группы `IO`/`HW` без железа.

## 6. Экран «Консоль CP/M»

| Элемент | Тип | Привязать к |
|---|---|---|
| Вывод консоли | Text / Text field | `GVL_CPM.Console_Out` |
| Строб вывода | Lamp | `GVL_CPM.Console_OutEn` |
| Ввод символа | Text field | `GVL_CPM.Console_In` |
| Есть символ | Lamp | `GVL_CPM.Console_InEn` |
| Последняя функция BDOS | Text | `GVL_CPM.Cpm_LastFunc` |
| Результат BDOS | Text | `GVL_CPM.Cpm_LastRet` |
| Счётчик вызовов BDOS | Text | `GVL_CPM.Cpm_FuncCnt` |
| Счётчик инструкций | Text | `GVL_CPM.Cpm_Insn_Cnt` |
| Ошибка диска | Text | `GVL_Disk.Disk_LastErr` |

**Как работает консоль.** Программа выводит символ через `OUT 12h` или
через BDOS 2/9. Символ попадает в `Console_Out`, поднимается `Console_OutEn`.
Для ввода: оператор вписывает код символа в `Console_In` и ставит
`Console_InEn := TRUE`; программа читает его через `IN 11h` или BDOS 1/11.

**Почему одно поле, а не терминал:** полноценный эмулятор терминала
(прокрутка, история) в HMI CODESYS строится на элементе «Трассировка» или
через внешнюю программу. Для проверки CP/M достаточно одного символа:
именно так работает реальная консоль на уровне портов.

## 8. Запуск эмулятора: пошагово

### Режим симуляции

1. Открыть `build/Z80_EMU.project`.
2. **Online → Simulation** (включить режим симуляции).
3. **Online → Login** (или `F5`).
4. **Debug → Start** (или `F5`).
5. Убедиться, что `PLC_PRG` выполняется: в Watch-окне `GVL_PLCVisu.Busy`
   должно быть `TRUE`.

**Почему сначала тесты:** эмулятор стартует с памятью, заполненной нулями
(`NOP`), и просто инкрементирует `PC`. Чтобы увидеть осмысленную работу,
нужно либо загрузить CP/M, либо прогнать тесты.

### Прогон тестов процессора

1. В Watch задать `GVL_Tests.Cpu_Test_Run := TRUE`.
2. `TEST_Z80` сам пройдёт шаги: остановит эмулятор, загрузит каждую команду
   в память, прокрутит нужное число сканов, сравнит результат.
3. Итог: `GVL_Tests.Cpu_Test_Total_Pass = 62`, `GVL_Tests.Cpu_Test_Fail_Count = 0`.

### Прогон тестов CP/M и I/O

1. В Watch задать `GVL_Tests_CPM.Cpm_Test_Run := TRUE`.
2. Тесты сами подадут на входы образ `A5h` и `1234h`.
3. Итог: `GVL_Tests_CPM.Cpm_Test_Total_Pass = 30`, `GVL_Tests_CPM.Cpm_Test_Fail_Count = 0`.

### Запуск программы CP/M

1. Задать `GVL_BootFlags.Cpm_Reboot := TRUE` — раскладываются перехваты
   BDOS (`JP 0F000h`), BIOS (`JP 0FA00h`), каталог и `HELLO.COM`.
2. Обнулить `GVL_Control.Emu_Reset`, затем задать `GVL_Control.Emu_Run := TRUE`.
3. Установить `PC` на `0100h` — это делается через
   `GVL_InitRegs.Init_PC := 16#0100` и импульс `GVL_InitRegs.Init_En`.

   *Почему вручную:* в реальном CP/M программу запускает CCP (консольный
   процессор), читая команду с терминала. CCP — отдельная большая программа,
   выходящая за рамки задания. Прямой старт с `0100h` даёт тот же результат.

4. На экране «Консоль» должна появиться строка `HELLO, CP/M 2.2`.
5. После `JP 0000h` сработает WBOOT — эмулятор вернётся в готовое состояние,
   `GVL_CPM.Cpm_Exit` станет `TRUE`.

### Отладка

| Что смотреть | Где |
|---|---|
| Текущая команда | `GVL_PLCVisu.IR` |
| Где находится процессор | `GVL_PLCVisu.PC` |
| Состояние флагов | `GVL_PLCVisu.Flag*` |
| Попадание в BDOS | `GVL_CPM.Cpm_LastFunc` (номер функции) |
| Ответ BDOS | `GVL_CPM.Cpm_LastRet` |
| Сколько вызовов было | `GVL_CPM.Cpm_FuncCnt` |
| Ошибки диска | `GVL_Disk.Disk_LastErr` |

## 9. Ускорение: несколько инструкций за скан

По заданию допускается `N` инструкций за скан, где `N` — настраиваемый
параметр. Место для него — `GVL_Control.Insn_Per_Scan : INT`.

**Как это сделать (не реализовано, оставлено точкой расширения):**
эмулятор уже разбит на фазы через `FB_Clock`, поэтому достаточно заменить
одиночный импульс на счётчик:

```
   GVL_Control.Insn_Per_Scan = 1  -- текущее поведение (одна команда)
   GVL_Control.Insn_Per_Scan = 50 -- в 50 раз быстрее, для CP/M
```

**Почему не включено сейчас:** при `N > 1` фазы `Clk_Decode` и `Clk_Exec`
должны следовать парами внутри скана, а `FB_Clock` формирует одиночные
импульсы по фронтам скана. Потребуется `FB_Clock` с внутренним счётчиком —
это отдельный блок, и менять его без прогона тестов на реальном времени
рискованно. Текущая архитектура даёт ровно одну команду за скан, что
соответствует основному требованию задания.

**Оценка производительности:** при цикле задачи `T#10ms` эмулятор выполняет
100 инструкций в секунду. Для CP/M это медленно (реальный Z80 — 2-4 млн
инструкций в секунду), но для демонстрации и отладки достаточно. Для
ускорения нужно либо уменьшить период задачи (`T#1ms` даёт 1000 инструкций
в секунду), либо реализовать `N` инструкций за скан по схеме выше.
