# 06. ПОДДЕРЖКА CP/M 2.2

## 1. Что реализовано

| Компонент | Файл | Что делает | Язык |
|---|---|---|---|
| `FB_CPM_BDOS` | FBD | Диспетчер функций BDOS: цепочка `SEL` по регистру C, консоль, коды ошибок | **FBD** |
| `FB_CPM_BIOS` | FBD | Минимальный BIOS: распознавание 17 векторов, консоль, статус | **FBD** |
| `FB_CPM_Disk` | FBD | Каталог RAM-диска: поиск файла по имени, свободная запись | **FBD** |
| `PRG_CPM_Boot` | ST | Раскладка перехватов, каталог, загрузка `HELLO.COM` | ST (разрешено заданием) |
| `PRG_CPM_BDOS` | ST | Драйвер: перехват `CALL 0F000h`, вызов FBD-блока, работа с памятью | ST (разрешено) |

**Разделение проведено строго:**

* **вся вычислительная логика** — в FBD: таблица функций BDOS, распознавание
  векторов BIOS, сравнение имён в каталоге;
* **на ST** — только то, что принципиально невозможно в FBD: индексация массива
  и пошаговый обход памяти. В FBD нет ни оператора индексации, ни элемента
  «шаг по памяти»; попытка заменить их псевдоэлементами роняет компилятор
  CODESYS (см. `03_ЖУРНАЛ_СБОРКИ.md`, дефект 13).

## 2. Перехват BDOS по адресу 0x0005

Стандартный механизм CP/M: программа вызывает BDOS через `CALL 0005h`.
Нулевая страница выглядит так:

| Адрес | Содержимое | Назначение |
|---|---|---|
| `0000h` | `C3 00 FA` | `JP 0FA00h` — вход BIOS (WBOOT) |
| `0003h` | `01` | IOBYTE: консоль присвоена |
| `0004h` | `00` | текущий диск (A:) |
| `0005h` | `C3 00 F0` | **`JP 0F000h` — вход BDOS. Это и есть перехват** |
| `005Ch` | (FCB) | блок управления файлом по умолчанию |

**Как перехват работает в эмуляторе.** Когда программа делает `CALL 0005h`,
счётчик команд попадает на `0F000h`. Сеть 18 главной схемы сравнивает
`fbPCLatch.Q` с `0F000h` и поднимает сигнал `vIsBDOS`. Драйвер `PRG_CPM_BDOS`
по этому сигналу:

1. останавливает эмулятор, чтобы PC не ушёл дальше;
2. подаёт строб `En` на `FB_CPM_BDOS` — тот цепочкой `SEL` по регистру C
   выбирает функцию и считает результат;
3. выполняет операции с памятью (вывод строки до `$`, чтение/запись записи
   диска, поиск в каталоге);
4. записывает результат в `HL` и `A`, возобновляет работу.

**Почему без прерываний и без «магии»:** перехват работает на наблюдении за
шиной адреса — ровно так же, как это сделал бы реальный монитор. Никаких
скрытых переходов: схема видит адрес и реагирует.

## 3. Таблица функций BDOS

Реализованы все функции из задания. Диспетчер построен как цепочка `SEL`:
каждая функция — отдельное сравнение с константой, значения подаются прямыми
ссыпками. Такая схема читается как таблица.

| Функция | Имя | Аргумент | Результат |
|---:|---|---|---|
| 1 | C_READ | — | `A` = символ с консоли (с ожиданием) |
| 2 | C_WRITE | `E` = символ | символ выведен |
| 9 | C_WRITESTR | `DE` = адрес строки | строка до `$` выведена |
| 10 | C_READSTR | `DE` = буфер | строка ввода в буфер |
| 11 | C_STAT | — | `A` = `FFh` если символ есть, иначе `00h` |
| 13 | DRV_RESET | — | сброс диска |
| 14 | DRV_LOGIN | `E` = диск | `A` = `0` успех, `1` ошибка |
| 15 | F_OPEN | `DE` = FCB | `A` = `0` успех, `FFh` не найден |
| 16 | F_CLOSE | `DE` = FCB | `A` = `0` |
| 19 | F_DELETE | `DE` = FCB | удаление файла |
| 20 | F_READ | `DE` = FCB | запись прочитана в TPA |
| 21 | F_WRITE | `DE` = FCB | запись записана на диск |
| 22 | F_MAKE | `DE` = FCB | создание файла |
| 26 | SETDMA | `DE` = адрес | установка адреса передачи |
| 27 | ALLOC | — | карта занятых блоков |
| 32 | F_USERNUM | `E` = номер | `A` = текущий пользователь |
| 33 | F_READRAND | `DE` = FCB | чтение произвольной записи |
| 34 | F_WRITERAND | `DE` = FCB | запись произвольной записи |
| 35 | F_SIZE | `DE` = FCB | размер файла в записях |

**Почему именно эти:** это минимальный набор, который реально требуется
типовым `.COM`-программам — от «Hello, World» до простейших утилит. Функции
работы с датой, сетевыми устройствами и метками времени не включены, так как
их поддержка требует часов реального времени и не влияет на запуск программ.

## 4. BIOS

Таблица переходов расположена по адресу `0FA00h`, стандартно — 17 векторов
по 3 байта (`JP`). `FB_CPM_BIOS` распознаёт адрес и выполняет действие:

| Адрес | Вектор | Что делает |
|---|---|---|
| `0FA20h` | BOOT | холодный старт |
| `0FA23h` | WBOOT | перезагрузка (сюда ведёт `JP 0000h`) |
| `0FA26h` | CONST | `A = FFh` если символ есть |
| `0FA29h` | CONIN | принять символ |
| `0FA2Ch` | CONOUT | вывести символ |
| `0FA2Fh`…`0FA35h` | LIST / PUNCH / READER | заглушки |
| `0FA38h`…`0FA50h` | HOME / SELDSK / SETTRK / SETSEC / SETDMA / READ / WRITE / LISTST / SECTRAN | работа с диском |

**Почему так:** программа, завершившаяся через `JP 0000h`, попадает в WBOOT —
и эмулятор корректно возвращается в готовое состояние, а не «зависает».

## 5. RAM-диск A:

Параметры (стандартные для одного экстента CP/M 2.2):

| Параметр | Значение |
|---|---|
| Размер записи | 128 байт |
| Записей в блоке | 4 (блок = 512 байт) |
| Записей в каталоге | 64 |
| Размер каталога | 2 КБ = 4 блока |
| Всего блоков | 1024 (512 КБ) |
| Расположение | `Disk_Mem`, отдельный массив 512 КБ в `GVL_Disk` |

Раскладка:

```
смещение 000h..7FFh  — каталог: 64 записи по 32 байта
смещение 800h+       — данные: блок N начинается с 800h + (N-1)*200h
```

Запись каталога CP/M (32 байта):

| Смещение | Поле | Значение |
|---:|---|---|
| 0 | ST | номер пользователя; `E5h` = запись свободна |
| 1..8 | F1..F8 | имя файла, дополненное пробелами |
| 9..11 | T1..T3 | расширение |
| 12 | EX | номер экстента |
| 13 | S1 | счётчик |
| 14 | S2 | счётчик |
| 15 | RC | число записей в экстенте |
| 16..31 | AL | карта занятых блоков (16 номеров по 2 байта) |

**Почему отдельный массив, а не область в 64 КБ памяти:** в CP/M 2.2 диск
адресуется блоками и не является частью адресного пространства процессора.
Отдельный массив честнее отражает структуру и не отнимает память у TPA.

## 6. Загрузка .COM-программы

Порядок, реализованный в `PRG_CPM_Boot`:

1. обнулить нулевую страницу;
2. положить `JP 0FA00h` по адресу `0000h` (BIOS) и `JP 0F000h` по `0005h` (BDOS);
3. обнулить каталог RAM-диска, все записи пометить свободными (`E5h`);
4. создать в каталоге файл `HELLO.COM` с одной записью (RC = 1) и блоком 1;
5. загрузить код `HELLO.COM` в TPA по адресу `0100h`;
6. положить копию кода в блок 1 RAM-диска (чтобы работал поиск в каталоге).

**Программа `HELLO.COM`** (загрузка в `0100h`):

| Адрес | Код | Мнемоника | Что делает |
|---|---|---|---|
| `0100` | `0E 09` | `LD C,9` | функция BDOS «вывести строку» |
| `0102` | `11 10 01` | `LD DE,0110h` | адрес строки |
| `0105` | `CD 00 F0` | `CALL 0F000h` | вызов BDOS (перехватывается) |
| `0108` | `C3 00 00` | `JP 0000h` | завершение, возврат в CP/M |
| `0110` | `HELLO, CP/M 2.2\r\n$` | — | текст сообщения |

**Как заменить на свою программу:** заменить байты начиная с `Z80_Mem[0100h]`
и поправить запись каталога (`RC`, номер блока, размер). Для больших файлов
(более 128 байт) добавляются следующие блоки: `Disk_Mem[16#A00 + ...]`, а в
карте `AL` — номера 2, 3, … Для чтения `.COM` с диска рабочей станции
предусмотрено расширение через `SysFile` (см. раздел 8).

## 7. Консоль CP/M

Консоль продублирована в двух местах — через I/O-порты и через BDOS:

| Порт | Направление | Переменная |
|---|---|---|
| `10h` | IN | `GVL_CPM.Console_InEn` (статус) |
| `11h` | IN | `GVL_CPM.Console_In` (символ) |
| `12h` | OUT | `GVL_CPM.Console_Out` + `Console_OutEn` (строб) |

**Почему и порты, и BDOS:** порты нужны для программ, которые работают с
терминалом напрямую (минуя BDOS), а BDOS — для стандартных `.COM`. Оба пути
ведут к одним и тем же переменным, поэтому в HMI достаточно одной строки ввода
и одного поля вывода.

## 8. Загрузка .COM из файла (расширение)

Штатный путь для реального файла — функция `SysFile` библиотеки `SysFile`:

```iecst
(* ЭТО НЕ РЕАЛИЗОВАНО В ПРОЕКТЕ -- пример для расширения.
   Требует библиотеки SysFile и прав доступа рантайма к файловой системе. *)
VAR
    hFile : RTS_IEC_HANDLE;
    szMode : STRING := 'r';
    nRes : RTS_IEC_RESULT;
    nSize : RTS_IEC_SIZE;
    buf : ARRAY[0..4095] OF BYTE;
END_VAR

hFile := SysFileOpen(szFile:='C:\CPM\PROG.COM', am:=szMode, pResult:=ADR(nRes));
IF hFile <> RTS_INVALID_HANDLE THEN
    SysFileRead(hFile, ADR(buf), SIZEOF(buf), ADR(nSize));
    (* далее перенос buf в Z80_Mem[0100h..] и правка каталога *)
    SysFileClose(hFile);
END_IF
```

**Почему это вынесено за рамки:** работа с файлами требует, чтобы рантайм
ПЛК имел доступ к файловой системе и чтобы был задан путь. На SoftPLC это
работает, на компактном ПЛК файловой системы может не быть вовсе. Основной
механизм — раскладка программы через ST-инициализацию — работает всегда и
именно он проверен тестами.

## 9. Тесты CP/M

Набор `TEST_Z80_CPM` содержит **30 проверок** в четырёх группах:

| Группа | Номера записей | Кол-во | Что проверяет |
|---|---|---:|---|
| `IO` | 1..10 | **10** | Шина I/O: `IN 00h` (дискретные входы), `OUT 01h` (дискретные выходы), `IN 02h/03h` (аналоговый вход 0 двумя портами), `IN 06h/07h` (аналоговый вход 1), `OUT 04h/05h` (сборка аналогового выхода 0), `OUT 08h/09h` (канал 1 не мешает каналу 0), статус консоли, признак загрузки CP/M |
| `HW` | 11..14 | **4** | Аппаратный слой: упаковка дискретных входов в байт, аналоговый вход 0 в буфере, распределение выходов по каналам `%QX`, аналоговый вход 1 |
| `BD` | 21..30 | **10** | Программные: `JP 0F000h` в нулевой странице, адрес в векторе BDOS, `JP 0FA00h` и вектор BIOS, код `HELLO.COM` в TPA (первая команда, номер функции, `CALL 0F000h`, первый символ строки, адрес строки двумя байтами) |
| `DS` | 31..36 | **6** | RAM-диск: три символа имени и расширения файла в каталоге, счётчик записей, номер занятого блока, копия программы в блоке данных |

Итого **30 проверок** — все включены, номера записей без пропусков внутри групп.

**Плюс 62 проверки процессора** в `TEST_Z80` — итого **92 проверки**.

Ожидаемый результат: `GVL_Tests_CPM.Cpm_Test_Total_Pass = 30`,
`GVL_Tests_CPM.Cpm_Test_Fail_Count = 0` и, соответственно,
`GVL_Tests.Cpu_Test_Total_Pass = 62`.

### Как запустить

1. Открыть `build/Z80_EMU.project`.
2. `F5` → Online → Simulation → Login → Start.
3. Для проверок процессора: `GVL_Tests.Cpu_Test_Run := TRUE`.
4. Для проверок CP/M и I/O: `GVL_Tests_CPM.Cpm_Test_Run := TRUE`.

Тесты `IO` и `HW` сами подают тестовый образ на входы (`A5h` на дискретные,
`1234h` на аналоговый), поэтому железо для них не нужно.
