Документ закрывает оба технических задания. Всё, что ниже, **измерено**, а не

## 1. Что сделано

**Эмулятор процессора Z80 в CODESYS 3.5, логика — только на FBD.**

| Требование ТЗ | Как выполнено |
|---|---|
| 16 команд Z80 | `LD r,r'`, `LD r,n`, `LD r,(HL)`, `LD (HL),r`, `ADD A,r`, `SUB r`, `INC r`, `DEC r`, `JP nn`, `JP Z`, `JP NZ`, `CALL nn`, `RET`, `HALT`, `DJNZ`, `IN A,(n)`, `OUT (n),A` — декодер `FB_DecoderZ80` |
| Регистры A,F,B,C,D,E,H,L + альтернативный набор | `FB_RegFileZ80`, 16 регистров, два порта чтения и канал записи |
| Регистры IX, IY, SP, PC, I, R | SP и PC — явное состояние в `GVL_Regs` (сети PC/SP в `PLC_PRG`), IX/IY/I/R — в `GVL_PLCVisu` |
| Флаги S,Z,H,P/V,N,C + хранимые F5/F3 | `FB_ALU_Z80` + `FB_FlagsRegZ80`, все правила Z80 |
| Память 64 КБ `ARRAY[0..65535] OF BYTE` | `FB_Memory64K` (единственный ST-блок, см. п. 5) + `GVL_Memory` |
| 256 портов ввода-вывода | `FB_IO_Ports`, карта портов в `GVL_IO` |
| Шины в GVL | `GVL_Bus`: адрес, данные, адрес HL, адрес операнда |
| Побитовые операции через BYTE ↔ `ARRAY[0..7] OF BOOL` | `FB_BitUnpack8`, `b_bool2byte`, упаковка/распаковка входов и выходов |
| Один скан ПЛК = одна команда (с точкой расширения) | `FB_Clock`, двухфазный такт; `GVL_Control.Scan_Insns` — параметр из ТЗ |
| ST только для инициализации памяти, загрузки .COM и тестовых данных | 8 ST-POU, все — из разрешённого списка (проверяет `check_tz.py`) |
| Без CFC и без библиотечных эмуляторов CPU | в проекте только FBD-схемы и собственные FB |

**Задание 2: CP/M 2.2 и аппаратный ввод-вывод ПЛК.**

* запуск `.COM`-программы: `HELLO.COM` загружается в TPA по адресу `0100h` и
  выводит строку через BDOS 9 (`PRG_CPM_Boot`, `FB_CPM_BDOS`);
* минимальный BDOS/BIOS: перехват `CALL 0005h` и `CALL 0FA00h…`, таблица функций
  BDOS цепочкой `SEL` по регистру C, векторы BIOS по 3 байта;
* консоль: порты `10h` (статус), `11h` (принять), `12h` (вывести);
* RAM-диск: `FB_CPM_Disk`, каталог на 64 записи, чтение/запись записей;
* **порты Z80 выведены на физические каналы ПЛК**: `%IX0.0…%IX0.7` (порт `00h`),
  `%QX0.0…%QX0.7` (порт `01h`), `%IW0/%IW1` (порты `02h/03h` и `06h/07h`),
  `%QW0/%QW1` (порты `04h/05h` и `08h/09h`);
* входы копируются в буферы в начале скана, выходы выставляются в конце:
  `FB_HW_IO_PLC` + `GVL_HW_Buffer`, инструкции Z80 работают только с буферами.

## 3. Что было главной проблемой и как решено

Проект собирался с нулём ошибок, но в симуляции **не работал**: тесты
процессора проходили 8 из 40. Причина — не в типах и не в языке, а в том, как
IEC-среда исполняет FBD. Ниже то, что выяснено измерением (`sim_dump_cpu.py`,
`sim_dump_cpm.py` печатают по каждому тесту IR, коды операции, номера регистров,
стробы, состояние PC и регистров).

| Класс проблемы | Суть | Решение |
|---|---|---|
| **Кольцо через переменную** | «регистры → АЛУ → регистры» внутри одного POU CODESYS разрывает **нулём**, а не значением прошлого скана | состояние вынесено в `GVL_Regs` парами `Rs_*`/`Nx_*` + программа-защёлка `PRG_RegLatch`, которая идёт в задаче после `PLC_PRG` |
| **Самоссылка FB** | `FB_PC_Z80`, `FB_SP_StackZ80`, `FB_FlagsRegZ80`, `FB_Reg16` держали состояние, читая собственный выход в той же сети | все переведены на явное состояние снаружи |
| **Чтение до присваивания** | переменная, читаемая в сети **до** своего `outVariable`, даёт значение прошлого скана | все промежуточные величины объявляются до вызова FB |
| **Fan-out выхода блока** | у клона может остаться неподключённый вход, и сравнение считает мусор | каждый потребитель получает свой экземпляр `inVariable`, константы не переиспользуются |
| **Порядок ветвей `SEL`** | `b_sel(G, IN0, IN1)` даёт **IN1** при `G = TRUE`; ошибка повторилась в трёх местах подряд | правило зафиксировано в `docs/04_СХЕМЫ.md` |
| **Двухфазный такт** | выборка кода и исполнение оказались в разных сканах, и команда исполнялась с управляющими сигналами предыдущей | фазы `Clk_Decode`/`Clk_Exec` разведены, фаза сбрасывается при остановке |
| **Адрес операнда** | в режиме «операнд из кода» адресом считался сам `nn` | операнд читается с `PC+1`, пара `nn` собирается выходом `Op_Word` |
| **Запись в память** | данные записи — результат АЛУ, а АЛУ считает после чтения: внутри скана это кольцо | отдельный порт `Wr_Addr/Wr_Data/Wr_Stb`, запись выполняется следующим сканом |
| **Флаги Z80** | H при вычитании считался формулой сложения, заём — отсутствием переноса суммы, у `CP` P/V считался чётностью | H — заём из бита 4, C — старший байт 16-битной разности, P/V для `CP` — переполнение, у INC/DEC флаг C сохраняется |
| **Оператор АЛУ** | вход A был жёстко подключён к регистру A (`INC B` считал A+1) | второй порт чтения `Dst_Val` и мультиплексор первого операнда |
| **Нумерация регистров** | код регистра Z80 (0=B…7=A) и номер в проекте (0=A…7=F) — разные вещи | явный перевод `(r+1) AND 7`, для (HL) — код 8 |
| **Порты и буферы** | данные `IN` не попадали в регистр, выход порта был импульсом, а не защёлкой, буферы выходов не заполнялись | данные порта поданы в тракт записи, порт стал защёлкой, буферы заполняются |
| **Два стенда на один процессор** | оба стенда управляют одним CPU и разрушают данные друг друга | жёсткий порядок: сначала CP/M, затем процессор; признаки запуска пишутся одним пакетом |

Отдельно: **таблица тестов была неверна в 34 ожиданиях из 40** (считалась
вручную). Например, у T09 (`ADD A,01h` при `A = FFh`) ожидался `F = 50h`, хотя
перенос есть и должно быть `51h`. Таблица пересчитана **независимой моделью
Z80** — `generator/tools/regen_tests.py`, отдельный код на Python, не связанный
с генератором схем. Это позволило отделить дефекты эмулятора от дефектов тестов.

## 5. Границы решений (что и почему именно так)

1. **`FB_Memory64K` написан на ST.** В FBD нет индексации массива, а попытка
   использовать `MEM_READ`/`MEM_WRITE` приводила к аварийному завершению
   компилятора. Это единственный ST-блок с логикой; вся остальная логика
   процессора — в FBD. Обоснование записано в шапке блока.
2. **Состояние вне FB.** Это выглядит как «лишние» 20 строк GVL, но это прямое
   следствие поведения среды: кольцо через переменную она разрывает нулём.
   Альтернатива (считать всё в одном скане без обратных связей) невозможна для
   регистрового файла.
3. **Два скана на команду.** Такт двухфазный: выборка, затем исполнение.
   Требование «один скан — одна команда» выполнено по производительности
   (одна команда за такт), а точка расширения из ТЗ (`Scan_Insns`) вынесена в
   `GVL_Control`.
4. **Тестовый образ входов.** В этой установке модули ввода-вывода не
   сконфигурированы, поэтому `%IX` всегда 0. Входы собираются как
   `OR(физический канал, тестовый образ)`; на реальной сборке тестовый образ
   равен нулю и ничего не меняет.
5. **Визуализация.** В ScriptEngine нет `create_visualization`, поэтому HMI
   остаётся ручной работой в IDE; в ТЗ её и не было. Зеркало для HMI
   (`GVL_PLCVisu`) полностью готово.

## 6. Как повторить результат

```powershell
cd <каталог проекта>

# 1. Сгенерировать схемы
python generator\gen_z80.py

# 2. Собрать проект (создание, импорт, компиляция, сохранение)
generator\run_build_log.cmd
#    ожидается: "Компиляция завершена -- 0 ошибок"

# 3. Прогнать тесты в симуляции
generator\run_sim.ps1
#    ожидается: "REZULTAT: VSE TESTY PROJDENY (62/0 i 30/0)"

# 4. Статические проверки
python generator\tools\check_tz.py
python generator\tools\tests_plan.py
python generator\tools\check_comments.py
python generator\tools\check_balance.py
```

Подробный разбор любого прогона:

```powershell
generator\run_sim.ps1 -Script "tools\sim_dump_cpu.py"   # log\sim_dump_cpu.txt
generator\run_sim.ps1 -Script "tools\sim_dump_cpm.py"   # log\sim_dump_cpm.txt
```

## 8. Честный перечень того, что осталось за рамками

| Пункт | Причина |
|---|---|
| 20 предупреждений `C373` | нет модулей ввода-вывода в установке (см. 2.1) |
| Визуализация (HMI) | нет API в ScriptEngine; вне ТЗ |
| Проверка на физическом ПЛК | на этой машине доступен только SoftPLC в режиме симуляции |
| Полный набор команд Z80 | ТЗ требует ровно 16; остальные (ADC/SBC,IX/IY-операции, битовые) не реализованы |
| CP/M: программы, кроме HELLO.COM | RAM-диск и BDOS готовы, но проверены на одной .COM-программе из ТЗ |
