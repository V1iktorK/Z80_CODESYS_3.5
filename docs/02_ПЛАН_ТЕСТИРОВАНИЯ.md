# ШАГ 2. ПЛАН ТЕСТИРОВАНИЯ — эмулятор Z80

## 1. Методология: как тестировать в FBD без `assert`

В FBD нет оператора `assert`. Тест строится как **схема сравнения**:

```
   Ожидание (CONST) ──┐
                      ├──► [ EQ ] ──► Test_Result[i] : BOOL
   Факт (GVL_PLCVisu)─┘
```

`EQ` даёт `BOOL` напрямую, а `BOOL` — это и есть PASS/FAIL. Результат теста —
бит в массиве, никаких исключений.

| Режим | Как работает | Для чего |
|---|---|---|
| `REGS` (0) | регистры готовятся напрямую, `TEST_Z80` проверяет | тесты команд и флагов |
| `PROGRAM` (1) | загрузка прошивки, `CYCLE_N` сканов, затем проверка | тесты программ |
| `LOOP` (2) | то же, с остановкой по счётчику | циклы DJNZ / DEC+JP NZ |
| `INTEGRITY` (3) | проверки целостности состояния | альт. набор, стек, HALT |

Формат хранения — `ST_TestCase` (DUT), массив `GVL_Tests.Tests : ARRAY[1..75]`:

```iecst
TYPE ST_TestCase :
STRUCT
    Id, Stage                       : INT;
    Opcode                          : BYTE;
    Init_A, Init_B, Init_F          : BYTE;
    Init_PC, Init_SP                : WORD;
    Exp_A, Exp_F                    : BYTE;
    Exp_PC                          : WORD;
    Exp_Cycles                      : INT;
    Mask_A, Mask_F, Mask_PC         : BOOL;
    Enabled                         : BOOL;
END_STRUCT
END_TYPE
```

Итог: `Test_Total_Pass = 62` и `Test_Fail_Count = 0` → всё зелёное.

## 2. Соглашения о флагах

| Бит | Флаг | Правило |
|---|---|---|
| 7 | **S** | `= Результат.7` |
| 6 | **Z** | `= (Результат = 0)` |
| 5 | F5 | логические — бит результата; `CP` — бит операнда. **Не тестируется** |
| 4 | **H** | ADD — перенос из бита 3; SUB/CP — заём из бита 4; INC/DEC — как ADD/SUB, но C не трогается; логические — 0 |
| 3 | F3 | как F5. **Не тестируется** |
| 2 | **P/V** | логические — чётность; ADD/SUB/CP — переполнение со знаком |
| 1 | **N** | 1 для SUB/SBC/CP/DEC; 0 для ADD/INC/логических |
| 0 | **C** | ADD — перенос из бита 7; SUB/CP — заём; **INC/DEC — не изменяется** |

Переполнение со знаком:
`ADD: P/V = (A.7 = B.7) И (A.7 ≠ Р.7)` ·
`SUB/CP: P/V = (A.7 ≠ B.7) И (A.7 ≠ Р.7)`

Контрольные значения чётности (совпадают с эмуляторами Z80):

| Результат | Единиц | P/V | Пример |
|---|---|---|---|
| `0x00` | 0 | **1** | `XOR A` |
| `0x03` | 2 | **1** | `OR A,03h` |
| `0x07` | 3 | **0** | `OR A,07h` |
| `0xF0` | 4 | **1** | `OR A,F0h` |
| `0xFF` | 8 | **1** | `OR A,FFh` |

## 3. Сводная таблица тестов (T01–T30)

| № | Команда | Вар. | Операнды | Ожидание | S Z H P/V N C |
|---|---|---|---|---|---|
| T01 | `LD B,n` | `06 42` | — | B=42h | — — — — — — |
| T02 | `LD A,n` | `3E 5A` | — | A=5Ah | — — — — — — |
| T03 | `LD C,B` | `48` | B=3Ch | C=3Ch | — — — — — — |
| T04 | `LD A,L` | `7D` | L=11h | A=11h | — — — — — — |
| T05 | `LD (HL),r` | `77` | H=20 L=00 A=AA | M[2000]=AAh | — — — — — — |
| T06 | `LD r,(HL)` | `7E` | M[2000]=55h | A=55h | — — — — — — |
| T07 | `ADD A,r` | `80` | A=25 B=10 | A=35h | 0 0 0 0 0 0 |
| T08 | `ADD` переп. | `80` | A=7F B=01 | A=80h | **1** 0 **1 1** 0 0 |
| T09 | `ADD` перенос | `80` | A=FF B=01 | A=00h | 0 **1 1** 0 0 **1** |
| T10 | `SUB r` | `90` | A=50 B=30 | A=20h | 0 0 0 0 **1** 0 |
| T11 | `SUB` заём | `90` | A=10 B=20 | A=F0h | **1** 0 **1** 0 **1 1** |
| T12 | `SUB` переп. | `90` | A=80 B=01 | A=7Fh | 0 0 **1 1 1** 0 |
| T13 | `INC A` | `3C` | A=0F, C=1 | A=10h, **C=1** | 0 0 **1** 0 0 **1** |
| T14 | `INC A` переп. | `3C` | A=7F, C=0 | A=80h | **1** 0 **1 1** 0 0 |
| T15 | `DEC B` | `05` | B=01, C=1 | B=00h, **C=1** | 0 **1** 0 0 **1** 1 |
| T16 | `DEC B` заём | `05` | B=00, C=0 | B=FFh | **1** 0 **1** 0 **1** 0 |
| T17 | `JP nn` | `C3` | — | PC=2000h | — — — — — — |
| T18 | `JP Z,nn` вып. | `CA` | Z=1 | PC=2000h | не меняются |
| T19 | `JP Z,nn` не вып. | `CA` | Z=0 | PC=PC+3 | не меняются |
| T20 | `JP NZ,nn` вып. | `C2` | Z=0 | PC=2000h | не меняются |
| T21 | `JP NZ,nn` не вып. | `C2` | Z=1 | PC=PC+3 | не меняются |
| T22 | `CALL nn` | `CD` | SP=FFFFh | PC=2000, SP=FFFD | — — — — — — |
| T23 | `RET` | `C9` | SP=FFFDh | PC=возврат, SP=FFFFh | — — — — — — |
| T24 | `HALT` | `76` | — | PC=PC+1, Halted=TRUE | — — — — — — |
| T25 | `DJNZ d` ветвь | `10 FE` | B=02h | B=01h, PC=PC | 0 0 0 0 **1** 0 |
| T26 | `DJNZ d` выход | `10 FE` | B=01h | B=00h, PC=PC+2 | 0 **1** 0 0 **1** 0 |
| T27 | `AND A,r` | `A0` | A=0F B=F0 | A=00h | 0 **1** 0 **1** 0 0 |
| T28 | `OR A,r` | `B0` | A=0F B=F0 | A=FFh | **1** 0 0 **0** 0 0 |
| T29 | `XOR A,r` | `A8` | A=FF B=FF | A=00h | 0 **1** 0 **1** 0 0 |
| T30 | `CP r` | `B8` | A=50 B=50 | A=50h (не изм.) | 0 **1** 0 0 **1 1** |

**Почему в T01–T06 много «—»:** `LD` — единственная группа, которая **не трогает
флаги вообще**. В `Init_F` задаётся `FFh`, и проверяется, что `F` остался `FFh`.
Это ловит частую ошибку — случайную запись в регистр F.

**Почему T13 и T15 проверяют C:** `INC`/`DEC` в Z80 **не изменяют флаг переноса**,
хотя меняют H, P/V, N. Начинающие почти всегда портят здесь C.

## 5. Тест программы: сложение двух чисел из памяти (P01–P05)

| Адрес | Код | Мнемоника |
|---|---|---|
| `0100` | `3A 00 20` | `LD A,(2000h)` |
| `0103` | `47` | `LD B,A` |
| `0104` | `3A 01 20` | `LD A,(2001h)` |
| `0107` | `80` | `ADD A,B` |
| `0108` | `32 02 20` | `LD (2002h),A` |

Данные: `M[2000h]=25h`, `M[2001h]=10h`.

| № | Проверка | Ожидание |
|---|---|---|
| P01 | `M[2002h]` | **`35h`** |
| P02 | `A` | `35h`, все флаги 0 |
| P03 | `B` | `10h` |
| P04 | `PC` | `010Bh` |
| P05 | `H`, `L` | не изменились |

**Почему `M[2002h]` — главная проверка:** она проверяет всю цепочку сразу:
выборку из памяти, косвенную адресацию `(nn)`, регистровый файл, ALU и обратную
запись в память. Если P01 прошёл — работает почти всё.

## 6. Тесты циклов (L01–L08)

### Вариант 1 — `DJNZ`

| Адрес | Код | Мнемоника |
|---|---|---|
| `0120` | `06 05` | `LD B,05h` |
| `0122` | `AF` | `XOR A` |
| `0123` | `80` | `ADD A,B` ← точка возврата |
| `0124` | `10 FD` | `DJNZ 0123h` |
| `0126` | `32 00 20` | `LD (2000h),A` |

| Итерация | A до | A после | B после DJNZ | Ветвь |
|---|---|---|---|---|
| 1 | 0 | 5 | 4 | да |
| 2 | 5 | 9 | 3 | да |
| 3 | 9 | 12 | 2 | да |
| 4 | 12 | 14 | 1 | да |
| 5 | 14 | **19 = 13h** | **0** | **нет** |

| № | Проверка | Ожидание |
|---|---|---|
| L01 | `M[2000h]` | **`13h`** |
| L02 | `B` | `00h` |
| L03 | `PC` | `0128h` |
| L04 | выполнено `DJNZ` | 5 |
| L05 | ветвлений | 4 |

**Почему счётчик именно 5:** нужно, чтобы цикл **и хотя бы раз повторился, и хотя
бы раз вышел без ветвления** — иначе тест не отличит «ветвление работает» от
«ветвления нет, просто дошло до конца».

**Почему `d = FD`:** `DJNZ` отсчитывает смещение **от адреса следующей команды**.
Команда на `0124h`, длина 2 → следующая `0126h`. Цель `0123h`.
Смещение `= 0123h − 0126h = −3 = FDh`.

### Вариант 2 — `DEC B` + `JP NZ`

| Адрес | Код | Мнемоника |
|---|---|---|
| `0140` | `06 03` | `LD B,03h` |
| `0142` | `AF` | `XOR A` |
| `0143` | `80` | `ADD A,B` ← возврат |
| `0144` | `05` | `DEC B` |
| `0145` | `C2 43 01` | `JP NZ,0143h` |

| № | Проверка | Ожидание |
|---|---|---|
| L06 | `A` | `3+2+1 = 06h` |
| L07 | `B` | `00h` |
| L08 | `Z` на выходе | `1` |

## 7. Тесты целостности (I01–I07)

| № | Проверка | Ожидание |
|---|---|---|
| I01 | альтернативный набор не мешает основному | `A` не изменился |
| I02 | `IX`/`IY` живут отдельно | `IX` не изменился |
| I03 | `I` и `R` | за 10 сканов `R` вырос на 10, `I` не изменился |
| I04 | стек не переполняется молча | `SP` циклический, ошибка в `Test_Overflow` |
| I05 | память целиком | `0000h`, `7FFFh`, `FFFFh` совпадают |
| I06 | `HALT` останавливает | `PC` не меняется, `Halted=TRUE` |
| I07 | `IR=00h` (NOP) | `PC=PC+1`, остальное не изменилось |

## 8. Регламент прогона и регрессии

```
1. Компиляция проекта            → 0 ошибок
2. PRG_InitMemory (ST)           → память обнулена
3. TEST_Z80 режим REGS           → T01..T30, F_*, F_ISO*
4. TEST_Z80 режим PROGRAM        → P01..P05
5. TEST_Z80 режим LOOP           → L01..L08
6. TEST_Z80 режим INTEGRITY      → I01..I07
7. Test_Total_Pass = 62          → ВСЁ ЗЕЛЁНОЕ
```

**Правило регрессии (жёсткое):** после любой правки схемы прогоняется **весь**
набор, а не только упавший тест. Причина: правка ALU легко ломает декодер.
Отчёт по каждому FAIL: «тест → ожидание → факт → PASS/FAIL → причина → правка».

**Ожидаемая хронология первой отладки:** первые прогоны обычно дают FAIL в
T13/T15 (флаг C у `INC`/`DEC`), F_H2 (заём вместо переноса) и L03/L05 (смещение
`DJNZ`). Это нормальный порядок отладки, а не признак неверной архитектуры.

## 9. Что тесты намеренно НЕ покрывают на этапе 1

| Исключено | Причина |
|---|---|
| F5/F3 как PASS/FAIL | храним, но не тестируем (требование задания) |
| `ADC`, `SBC`, `DAA`, сдвиги | вне списка базовых команд |
| Точные T-состояния | по архитектурному договору тактов нет |
| Прерывания, `IM`, `EI`/`DI` | вне списка |
| `IN`/`OUT`, `IX`/`IY` со смещением | вне списка |
| `ADC`/`SBC` с переносом | в ALU реализованы, в таблицу тестов не включены |

## 10. Что реализовано (фактический состав набора)

В `TEST_Z80` заведено **62 проверки**, все включены (`Enabled := TRUE`),
номера 1..62 без пропусков:

| Группа | Номера | Кол-во | Что проверяется |
|---|---|---:|---|
| `T` — команды | 1..30 | 30 | `LD` (6), `ADD`/`SUB` (6), `INC`/`DEC` (4), `JP` (5), `CALL`/`RET`/`HALT` (3), `DJNZ` (2), логика и `CP` (4) |
| `F` — флаги | 31..50 | 20 | S, Z, H, P/V, N, C по отдельности, плюс изоляция флагов (`LD` не трогает F, `JP Z` при Z=0 не трогает F) |
| `P` — программа | 51..55 | 5 | сложение двух чисел из памяти: результат в `M[2002h]`, A, флаги, PC, сохранность H/L |
| `L` — циклы | 56..60 | 5 | `DJNZ` (5 итераций → `13h`) и `DEC B` + `JP NZ` (3 итерации → `06h`) |
| `I` — целостность | 61..62 | 2 | альтернативный набор не мешает основному; `SP` не влияет на ALU |

Ожидаемый результат: `GVL_Tests.Cpu_Test_Total_Pass = 62`,
`GVL_Tests.Cpu_Test_Fail_Count = 0`.

### Как устроен прогон

Каждый тест проходит четыре шага (`GVL_Tests.Cpu_Test_Stage`):

| Шаг | Что происходит |
|---:|---|
| 0 | эмулятор остановлен, ищется следующий включённый тест |
| 1 | загрузка памяти и начальных регистров |
| 4 | снимается `Init_En`, эмулятор запускается |
| 5 | прокручивается `Exp_Cycles` сканов (один скан = одна команда) |
| 2 | `FB_TestCase` сравнивает факт с ожиданием через блоки `EQ` |
| 3 | подсчёт итогов, переход к следующему тесту |

**Как задаются начальные регистры.** Через порт инициализации
`FB_RegFileZ80` (`Init_En`, `Init_Sel_Dst`) и массив `GVL_InitRegs.Init_Vals[0..15]`.
Порядок совпадает с кодами `Sel_Dst`: `0=A 1=B 2=C 3=D 4=E 5=H 6=L 7=F`,
далее альтернативный набор. Это позволило проверять команды, которым нужны
предустановленные `H`/`L` (например `LD (HL),A`) и `SP` (для `CALL`).

**Дополнительная проверка памяти.** Если у теста поднят `Mask_Mem`, результат
сравнивается не только по регистрам, но и по ячейке
`Z80_Mem[Exp_Mem_Addr]`. Именно так проверяются `LD (HL),A`, программа
сложения и циклы.
