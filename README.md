# Z80_EMU — эмулятор процессора Z80 на FBD в CODESYS 3.5

> Эмулятор Z80 + CP/M 2.2 на FBD в CODESYS 3.5

Учебный проект (портфолио, 5 семестр, 15.03.04 «Автоматизация технологических
процессов и производств»). Логика процессора целиком собрана **на FBD-схемах**
CODESYS; ST применён только там, где это разрешено заданием (инициализация
памяти, загрузка `.COM`, тестовые данные).

## Z80 или Intel 8080?

Эмулятор **Zilog Z80**, а не 8080: набор команд задания включает то, чего у
8080 нет — альтернативный набор регистров, `DJNZ`, `IX`/`IY`, отдельный регистр
`R`, флаги `F5`/`F3`. При этом Z80 **надмножество** 8080: программы для 8080
(в том числе CP/M-программы) на нём работают, поэтому CP/M 2.2 и запуск `.COM`
здесь полноценные. Если нужна именно маркировка «8080» в названии — скажите,
поменяю описание репозитория, но технически это Z80.

## Что внутри

* **Процессор Z80** — 17 команд задания: `LD r,r'`, `LD r,n`, `LD r,(HL)`,
  `LD (HL),r`, `ADD A,r`, `SUB r`, `INC r`, `DEC r`, `JP nn`, `JP Z`, `JP NZ`,
  `CALL nn`, `RET`, `HALT`, `DJNZ`, `IN A,(n)`, `OUT (n),A`.
* **Регистры** A,F,B,C,D,E,H,L и альтернативный набор, IX, IY, SP, PC, I, R.
* **Флаги** S, Z, H, P/V, N, C и хранимые F5/F3 — по правилам Z80.
* **Память** 64 КБ, **256 портов** ввода-вывода, шины в GVL.
* **CP/M 2.2** — запуск `.COM`, перехват BDOS/BIOS, консоль, RAM-диск.
* **Аппаратный слой** — порты Z80 выведены на `%IX/%QX/%IW/%QW` через буферы:
  входы копируются в начале скана, выходы выставляются в конце.

## Требования

| Что | Версия / примечание |
|---|---|
| ОС | Windows (проверено на Windows 10/11) |
| CODESYS | 3.5 SP17 (проверено на `3.5.17.30`), профиль `CODESYS V3.5 SP17 Patch 3` |
| Среда исполнения | `CODESYS Control Win V3` — проект создаёт устройство сам |
| PowerShell | 5.1 (входит в Windows) |
| Python | 3.8+ (проверено на 3.14). Сторонние пакеты **не нужны** |

`CODESYS.exe` ищется автоматически: параметр `-Exe`, переменная окружения
`CODESYS_EXE`, стандартный путь `3.5.17.30`, затем любая установленная версия в
`Program Files`. Если у вас другая версия — укажите профиль явно:

```powershell
generator\run_build_log.cmd -Profile "CODESYS V3.5 SP18 Patch 1"
```

## Быстрый старт

Три команды из корня проекта:

```powershell
# 1. Сгенерировать FBD-схемы и GVL из единого источника (generator\gen_z80.py)
python generator\gen_z80.py

# 2. Собрать проект в CODESYS без UI: создать, импортировать, скомпилировать
generator\run_build_log.cmd

# 3. Прогнать тесты в симуляции и прочитать результаты
powershell -NoProfile -ExecutionPolicy Bypass -File generator\run_sim.ps1
```

**Что должно получиться.**

Шаг 2 — в конце вывода (файл `log\codesys_out.txt`):

```
Компиляция завершена -- 0 ошибок, 20 предупреждений : готово к загрузке
```

20 предупреждений — это `C373: Адрес %IX0.0 не задан ни в одном устройстве`
(и такие же про `%QX`, `%IW`, `%QW`). Причина — в установке нет модулей
ввода-вывода, см. раздел «Известные особенности». Собственных предупреждений
проекта ноль: первая фаза компиляции даёт «0 ошибок, 0 предупреждений».

Шаг 3 — в конце вывода:

```
REZULTAT: VSE TESTY PROJDENY (62/0 i 30/0)
```

## Открыть схемы в IDE

После шага 2 проект лежит в `build\Z80_EMU.project` — откройте его в CODESYS.
Главная схема: `PLC_PRG` (сети идут в порядке исполнения), декодер команд:
`FB_DecoderZ80`, АЛУ: `FB_ALU_Z80`.

## Состав репозитория

```
generator/
  gen_z80.py        генератор всех схем и ST-текстов — единственный источник правды
  build.py          сборка проекта в CODESYS без UI (ScriptEngine)
  tools/fbd_xml.py  библиотека PLCopenXML: Network, Pou, Gvl, TextPou
  tools/*.py        проверки и отладочные инструменты
  run_build_log.cmd сборка (тонкая обёртка над run_build_log.ps1)
  run_sim.ps1       прогон в симуляции
src/                32 .plcopenxml + 16 .gvl — результат генерации (вход сборки)
docs/               планы, журнал сборки, схемы, отчёты
build/ log/         артефакты (в git не входят)
```

Полезные инструменты:

| Файл | Что делает |
|---|---|


## Известные особенности

1. **20 предупреждений `C373`.** Адреса `%IX0.0…%IW1` объявлены в `PLC_PRG`, но
   в этой установке нет модулей ввода-вывода: среди 776 описаний устройств нет
   слайсов `DI/DO/AI/AO` для SoftPLC, а `dev.add("Digital Input")` отвечает
   отказом. Убирать адреса нельзя — их требует ТЗ (порты Z80 на физические
   каналы через дерево устройств). На реальном ПЛК с модулями предупреждения
   исчезают без правок кода.
2. **Один такт — одна команда, два скана на команду.** Такт двухфазный:
   выборка кода, затем исполнение. Точка расширения из ТЗ
   (`GVL_Control.Scan_Insns`) присутствует в GVL.
3. **Тестовые стенды выполняют по одной команде на проверку.** Это осознанное
   решение: последовательность команд в этой архитектуре идёт со сдвигом
   (выборка кода и чтение операнда разнесены), и стенд проверяет команду
   изолированно. Подробно — `docs/04_СХЕМЫ.md`, правило 5.
4. **CODESYS — однопользовательское приложение.** Обёртки убивают только свои
   процессы (с `--runscript`/`--noUI`), чужие не трогают. Если CODESYS уже
   открыт вручную, закройте его перед сборкой.
5. **Визуализация (HMI)** — ручная работа в IDE: в ScriptEngine нет
   `create_visualization`. Зеркало для HMI (`GVL_PLCVisu`) готово.

## Если что-то не запускается

| Симптом | Что делать |
|---|---|
| `NE NAJDEN CODESYS.exe` | укажите путь: `generator\run_build_log.cmd -Exe "C:\...\CODESYS.exe"` |
| CODESYS завершился с кодом 1 и пустым выводом | почти всегда чужой запущенный CODESYS; закройте его |
| Сборка идёт дольше 900 с | таймаут; увеличьте: `generator\run_build_log.cmd -TimeoutSec 1800` |
| `Ошибка профиля` / профиль не найден | `-Profile "<имя профиля из вашего CODESYS>"` |
| Тесты дают 0/NN | проект собран из старых `src/`; повторите шаги 1-2 |
